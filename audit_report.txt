----------------------------------------------------------------
1. PROBLEMS FOUND
----------------------------------------------------------------

[A] Production-breaking bugs
1. core/views.py — custom 404/403/500 handlers rendered
   "errors/404.html" / "errors/403.html" / "errors/500.html", but
   those templates do not exist. With DEBUG=False, any 404/403/500
   cascaded into "TemplateDoesNotExist errors/500.html" (verified).
   The real templates live at templates/{404,403,500}.html.

2. templates/notes/note_list.html — uses {% static %} in the
   extra_js block without {% load static %}, so /notes/ raised a
   TemplateSyntaxError (500). Only caught by actually rendering the
   page; manage.py check does not detect it.

[B] Functional bugs
3. dashboard/views.py vs static/js/charts.js — the view emitted
   nested JSON (task_status, task_priority, notes_by_category) but the
   JS reads flat keys (completed_tasks, pending_tasks,
   priority_low/medium/high, notes_categories, notes_category_counts).
   All dashboard charts always showed "No data yet."

4. ai_assistant/views.py — AI history excluded EVERY past message
   whose text matched the new one, instead of only excluding the just
   created message. Repeating a question silently dropped older
   duplicates from the AI context.

5. smoke_test.py — used django.test.Client whose default host
   "testserver" is not in ALLOWED_HOSTS (every request returned 400),
   and two URLs were wrong: /export/notes/pdf/ (real:
   /notes/export/pdf/) and /ai-chat/new/send/ (real: /ai-chat/send/).

[C] Security issues
6. accounts/views.py — the login ?next= parameter was passed straight
   to redirect(), an open redirect (verified that
   ?next=https://evil.example.com followed the off-site URL after
   login).

7. templates/dashboard/home.html — {{ charts_json|safe }} inside a
   <script> block is a stored-XSS vector: a category name such as
   "</script><script>..." can break out of the JSON block.

[D] Minor issues
8. config/settings.py — conflicting DEBUG defaults
   (environ.Env(DEBUG=(bool, False)) vs env.bool("DEBUG",
   default=True)); a missing .env would run the app in development
   mode.
9. accounts/models.py Profile.image_url referenced
   /static/images/default-avatar.svg, which did not exist -> broken
   avatar image.
